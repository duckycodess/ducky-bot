# Design

## Context

See proposal. Discord currently keys messages by channel; `ChannelRolePolicy` matches exact channel IDs. `ConversationsRepo` trims to 200 rows and OpenClaw owns a second, persistent session keyed by digest(user, thread). `/forget conversation` deletes only Ducky rows. Authorization is frozen env config; owner-only command/component manifests are asserted at router startup.

## Goals / Non-Goals

**Goals:** One native thread per eligible starter; durable explicitly scoped shared participation; complete application transcript, budgeted model context, honest targeted provider deletion; preserved owner-only boundaries.

**Non-Goals:** Giving chat users command/tool access, deleting Discord messages, claiming unsupported OpenClaw deletion works, or introducing a new ticket worker.

## Decisions

1. **Native thread entry with one authorization source.** Put the eligibility decision in a testable policy and the effect behind a thread-starter port implemented by the Discord transport and faked in tests. Use the one frozen `Authorizer.roleOf` and profile-scoped configured conversational parents; exclude bots/webhooks, DMs, child threads, non-chat and shared channels. Call Discord `startThread` on the starter message with a fixed, sanitized/redacted name (at most 100 characters) and seven-day auto-archive; route the starter once using the returned thread ID. Persist a unique starter-message mapping; recover `MESSAGE_ALREADY_HAS_THREAD` (160004) by the documented starter-message ID identity, handle 429 through Discord's rate handling, and refuse visibly on creation failure without parent fallback. Archived-but-unlocked children can resume; locked/inaccessible/missing ones fail explicitly. Carry `parentChannelId` on child contexts for role/routing and shared-channel exclusion, never as independent authority. Preserve one config/role conflict check and status projection.
2. **Reply references and controls.** Resolve Discord references only within the same visible thread, clamp/sanitize text, and label unavailable/cross-thread anchors unavailable; replies do not change threadKey. Branch creates a new visible thread with only the selected accessible anchor and a distinct session. Declare a positive `CONVERSATIONAL_INTERACTION_KINDS` manifest separate from `OWNER_ONLY_INTERACTION_KINDS`; assert their union, dispatch on an explicit allowlist and recheck authz/participation for each press. Keep `SHARED_READABLE_ROUTES` strictly reads. Component events carry signed actor/thread/message identity (safe compact ID under 100 characters), not trust in a supplied channel; per-actor buttons require the signer to match the presser. Record this new non-owner conversational surface in an ADR.
3. **Separate durable transcript and bounded prompt state.** Additive SQLite migration preserves full per-thread turns without append-time row cap, starter mapping, explicit participant records, checkpoint and provider-session epoch. A thread-scoped read MUST require a participation proof produced by verified authorization/participation, with no unscoped read: explicitly supersede ADR 0021 §2/§3 and test this structural guard. Keep private DM/user sessions separate; never replay private turns into shared threads. Compact snapshot derives durable decisions plus recent turns; manual and automatic triggers share one implementation, bounded by a configured conservative byte budget (no provider token limit is recorded), refusing a turn that cannot fit. Commit turns atomically and persist checkpoint across restarts. Retain full history while thread exists as issue #4 requires; define deleted-thread cleanup and document storage/privacy tradeoffs and owner-managed deletion for a guest who cannot invoke owner-only `/forget`. Update ADR 0020/0021/0022/0024 and docs/SECURITY.md accordingly.
4. **Provider state and Forget.** First extend the safe OpenClaw probe to record sessions/transcripts/memory help capability names, without session values; verify a narrow deletion command and independent readback before allowing it. If unsupported or forbidden by `ALWAYS_FORBIDDEN_COMMAND_VERBS`, do not relax global policy: return partial deletion honestly. Keep provider sessions per actor+thread, but record the identities associated with a shared thread so thread deletion can address every contaminated actor session; never reuse a provider session after failed/unsupported deletion. Persist an epoch for rotation, and explicitly report that rotation orphans old provider data rather than erasing it. Keep current `/forget conversation` all-user scope by default and add an explicitly scoped option only if safe under the closed owner-only command manifest; audit counts only, no wildcard or wipe-all path. Use `runArgv` exclusively.
5. **Presentation and triggers.** Make conversation copy plain and concise with real Branch/Compact buttons; ensure any grilling copy in this build is numbered with concise recommendations. No `$grill-me`/`$ticket`/`$agentize` workflow trigger dispatcher exists in this repository: do not invent one. If future integration introduces one, only an initial unquoted first token may trigger it; quotes/code/bot notifications stay data. Remove timezone/reminder prose only at presenter level, leaving scheduling unchanged.

Alternatives rejected: using parent channel as conversation key (cross-thread leakage); using provider transcript as application full history (no Ducky retention/deletion control); truncating stored history for compaction (violates retention); trusting visibility as authorization (violates owner-only rule); interpreting unsupported deletion as success (misleads the user).

## Risks / Trade-offs

- [Discord permissions / archived state] -> Fail visibly and avoid alternate-context replies; test API behavior with a development guild where available.
- [Provider undocumented deletion semantics] -> Probe safe read-only surface first, implement only verified narrow deletion, otherwise mark provider deletion incomplete and rotate session identity.
- [Concurrent starters and turns] -> Unique starter mapping and serialized per-thread mutation/transaction, with idempotent retries.
- [Shared participant disclosure] -> Require explicit participation in visible thread, keep private DM/provider keys separate, and bound anchors to the current thread.
- [Storage growth] -> Retain full history while live; document and implement lifecycle-aware age retention of closed/deleted threads without wipe-all deletion.

## Migration Plan

Apply a numbered hand-rolled additive SQLite migration for thread mapping, participation, checkpoint, epoch and expanded transcript semantics; verify with `pnpm migrate --dry`, preserve old rows and do not reinterpret legacy parent-channel conversations as child-thread history. Configure channel policy before enabling native thread spawning; restart uses persisted IDs. Rollback disables new entry and leaves data private rather than merging sessions. Never silently migrate old provider session keys into a newly shared thread. The current issue's explicit owner-approved native-thread requirement supersedes the earlier follow-only proposal in docs/ROADMAP.md:436-482; update CURRENT_STATE and ROADMAP to record this reversal instead of silently choosing one.
