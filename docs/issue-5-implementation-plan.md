# Issue 5 implementation plan

Owner authorization: dispatcher entered via `agent:ready`. No deployment, merge, production configuration change, public/Funnel listener, second backend or ticket runner. The owner-only manifests remain authoritative and must be extended for new interaction kinds, never shared-read kinds.

1. Parsing and persistence: bounded explicit numbered multiline lists with parenthesized month-name day and optional AM/PM clock; yearless dates resolve to the next civil occurrence at or after today in the configured owner timezone within the existing horizon. Refuse unrecognized/ambiguous numeric dates, invalid day/month, or uncertain parse with a clarification rather than guessing. Extend `parseWhen` only if its other callers and `WHEN_HELP` are updated/tested; otherwise isolate the new grammar in a bulk parser. `due_all_day` exists already. Overdue SQL must compare timed due_at to now and all-day due_at to the start of the current local day (DST-safe), and update TasksService overdue and BriefingService list/count callers.
2. Bulk preview/save: use a bounded owner-scoped durable preview with TTL, limited pending previews per owner and atomic discard/expiry; store no credentials. Key uniqueness is `(owner, idempotencyKey)`; retries return the same task set. Transactionally validate the whole batch and both open-task and scheduled-reminder caps before inserts; a failed save leaves no tasks/reminders and an actionable preview error. Retention and `/forget` must handle preview data. The Discord flow should reuse the one-pending-per-(owner,thread) proposal machinery and TTL, respect role narrowing, and never interpret quotes/code/bot/notification messages as task lists. Phone uses the same domain preview/save semantics.
3. Linked reminders: persist a task link on reminder rows (not inferred from text); atomic creation/resync. Timed deadlines schedule future 24h and 1h offsets; date-only deadlines schedule 08:00 on due day. Already-past offsets are skipped without failing save or generating immediate sends (including same-day post-08:00 dates). Closing/editing a task cancels pending linked reminders and undelivered occurrences; preserve delivered history. Snooze creates a bounded new one-shot linked reminder (with cap check), keeping task.due_at unchanged. `/forget` and retention must not orphan live linked notifications: cancel/delete outstanding linked notifications transactionally and skip/count still-live records per existing policy. Preserve ledger send/ack crash window; never promise exactly-once.
4. Delivery and Discord: add an opt-in, profile-isolated reminders channel setting (unscoped/dev/prod) and validate it against role/shared collisions; update status/config docs. Route *only* task-linked reminders there with owner mention; unrelated reminders or unconfigured channel still go to owner DM, wrong owner abandoned. New signed owner-only interaction kinds for preview Save/Edit/Discard and card Done/Edit/Snooze must be in `OWNER_ONLY_INTERACTION_KINDS`, never `SHARED_READABLE_ROUTES`; recheck owner at every click, sign a changing task version and refresh cards after mutation. Cards show title and configured local date/time without timezone suffix or rejected reminder schedule line; document the issue-specific display deviation from ADR 0014's default Discord timestamps. Do not print internal UUIDs.
5. Phone: add an opt-in small mobile home-screen HTML page and fetch-JSON API on existing Fastify server, leaving the executor's application/json raw-body HMAC path unchanged. Distinct profile-scoped owner human credential/session, constant-time verification, httpOnly secure SameSite cookie with CSRF protection and bounded expiry; no credential or text logging. Fail closed on unconfigured auth or public bind, allow loopback, RFC1918, 100.64.0.0/10 and fd7a:115c:a1e0::/48 only; no Funnel. Binding executor's shared listener on a tailnet address also exposes signed executor routes to that tailnet, so keep executor authentication enforced. Size/rate limits and escaped HTML are mandatory.
6. Verify focused parser, time rollover, transaction/idempotency, human auth, routing, card, reminder lifecycle, outage and migration tests; `pnpm migrate --dry`, `pnpm typecheck`, `pnpm test`, `pnpm build`, migration rehearsal against a disposable backup, source-scanning invariants and final diff inspection. Log the manual Tailscale/Discord phone check as blocked with remedy if unavailable; never claim it passed. At least two meaningful commits as implementation lands, then independent read-only final review of exact pushed head. Leave bead in_progress awaiting dispatcher merge.

Implementation notes: the preview id itself became the owner-scoped idempotency key, and durable previews replaced per-thread in-memory proposal state so the phone can resume after restart. Previews expire via the reconciler independent of retention. The existing `/task list` controls stayed unchanged; the new cards belong to the bulk/deadline path. These choices are verified in the accompanying tests and ADRs.
