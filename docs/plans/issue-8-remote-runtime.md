## Implementation

1. Keep the existing remote Linux checkout and runtime. Add user-scoped coordinator service template alongside executor and profile-isolated env/state paths, without activating it. Write a remote-specific preflight/runbook for existing Tailscale SSH, loopback/private listener binding, no Funnel, linger, real cgroup user-slice MemoryMax/MemoryHigh/MemorySwapMax/TasksMax and cleanup timer readback. No second clone, provisioning or secret material in git. Supersede obsolete Azure/WSL instructions with an ADR, preserve the templates for history, and update CURRENT_STATE with honest host-specific evidence. User-unit limits do not bound Herdr agents (children of Herdr server) and require controller delegation; coordinator or executor OOM requires reconciliation, not assumed success.
2. Preserve the recorded OpenClaw Codex subscription route and profile store, but do not infer quota counts or a runtime OAuth/API-key route from an unrecorded command. Extend the existing read-only probe/contract before making such a claim, or mark route/quota eligibility unverified and fail closed rather than silently switching provider. Explicitly disable additional-user conversation at the authz chokepoint by default, test that a non-owner calls no provider, and document that the friend chat role has zero surface until independently authorized. Owner deterministic reminders/GitHub events must not depend on the model.
3. At the coordinator's claim transaction introduce a default-one Ducky-local, host-independent engineering admission cap (a guarded global slot plus existing per-repo reservation) with tests for two repositories/executors; a held slot returns no claim, leaving the second job queued without backoff. Extend ADR 0010 rather than silently changing its per-repo spans. Protect new reservation data from retention, include it in backup/schema assertions and update probe-live-job preflight. Retain admission through lease expiry until the same job can prove quiescence or an owner cleans up; answered paused jobs must reacquire it. Persist the attempt deadline so restart/reclaim cannot reset a live attempt budget. Cross-program global safety remains blocked. Add a fail-closed executor memory-headroom check before claim using the user-slice limit and current usage, with engineering and notification reserves. Templates must document that Herdr owns agent processes outside the executor cgroup; pin a Ducky session rather than borrowing the dispatcher's session, without activating another runtime.
4. Configure default 60-minute budget for each *claimed executor turn/attempt* (claim to terminal or pause), not owner/approval/dependency waits, which retain their existing durations. Coordinator is authoritative; use a backwards-compatible optional claim field and enforce a bounded local ceiling during rolling restarts. On timeout use the supervised cancellation path and report available phase/checkpoint. The recorded adapter has no supported active-agent interruption, so a working agent becomes an orphan, not a fabricated successful stop. Owned-descendant termination remains blocked pending an authorized real-agent stop probe. Do not invent kill trees or keystroke-based stop guarantees. Confirm quiescence through Herdr agent get. Release a global slot only on confirmed quiescence. If agent still works, retain the slot and orphan reservation for explicit owner cleanup. Keep ADR 0010's intentional host file-lock release on paused jobs intact and update adapter timeout/probe-budget invariants.
5. Automatic cleanup may touch only provably Ducky-owned, inactive workspaces past the existing TTL and stale Ducky-owned temp artifacts with ownership checks. Use a Ducky-specific TMPDIR outside devwork and agent-flow cleanup roots. Existing devwork cleanup understands neither Ducky activity nor its orphan ownership; process reclamation is not thereby verified. Never auto-clear orphan_agent reservations, live writers, detached sessions, transcripts, task records or provider state, nor touch another user's files. An orphan requires explicit owner inspection and cleanup.

6. Gate additional-user model work and Branch/Compact controls by default, including existing native-thread participants. Preserve owner-only commands and shared narrow reads. Reject separately billed API-key environment names in subscription-only runtime configuration without printing values; check provider/Herdr environment independently in the runbook because agents inherit the server environment. Do not invent quota counts or distinguish sign-in from quota without a recorded response; an idle engineering turn without a result pauses without consuming retry budget, only releasing admission after confirmed quiescence.
7. Add an ADR amending the earlier deployment/reservation assumptions. Reconcile contradictory historical provider evidence in CURRENT_STATE explicitly, rather than overwriting it with a new verification claim. The coordinator HTTP and phone page share one listener: use loopback plus tailnet-only Serve, or a tailnet bind, never invent an independent phone listener. Provider stays loopback with its own auth, no Funnel.

## Implementation checkpoint (2026-10-13)

The implementation is preparation, not complete acceptance. The admission slot is scoped to one coordinator database, not both profiles or agent-flow. Engineering is disabled by default. Claimed attempts carry a persisted deadline and time out through conservative supervision; active-agent termination is still unsupported. The cgroup guard is available and selected by remote templates, but cannot atomically reserve cross-program headroom. Additional-user AI is disabled by default. Environment-key refusal is partial evidence only.

Explicitly incomplete plan items: idle/no-result quota pause without retry consumption; provider auth/quota integration on this host (OpenClaw absent); configured dedicated Ducky Herdr session; periodic orphan-process/workspace reclamation (the reconciler only lists candidates). Owned temp sweep is hardened but does not establish active-job protection for arbitrarily long temp artifacts. These limitations are not silently waived and remain acceptance/merge blockers along with live Discord, logout, phone and controlled-job checks.
