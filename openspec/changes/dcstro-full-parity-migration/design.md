## Decisions

### 1. Evidence precedes public implementation

Privately derive semantic rules for recurrence, exception targeting, reminder states/resync/catch-up, watch selection and discovery, event identity/cursor inclusivity, alert versus digest settlement, briefing preferences and delivered-slot day keys. Record supported/unsupported fields and conditions in 0600 evidence in a 0700 external directory. Audit schedule-event notification behavior explicitly. Full parity means unsupported active behavior requires support or an explicit blocker, never silent normalization or an omitted subset. Use only the capabilities established by this audit. Fresh live inventory remains required before cutover.

### 2. Versioned boundary and atomic offline import

Strict whole-document validation in contracts, explicit profile/frozen owner/timezone agreement, bounded categories and length/temporal validation. Runtime files and database paths are explicit, private and outside worktree. Importer is an operator CLI beside backup scripts, not a Discord/phone route. It refuses malformed, unsupported, foreign-owner, incompatible configuration or over-capacity documents before any committed write. Require the target coordinator stopped and backup verified; do not claim a CLI acknowledgement proves a process is stopped. Import via service-owned orchestration and import-specific repository methods, one `BEGIN IMMEDIATE` transaction, with no transport or network side effects. Add a shared coordinator/importer exclusive runtime liveness lock if compatible with existing lifecycle; otherwise mechanically refuse CLI application until an authorized operator demonstrates the stopped-target gate. `BEGIN IMMEDIATE` alone does not prevent a live WAL coordinator from writing afterward.

Preserve terminal state, creation/update/completion times, instants and explicit deadline kind. Collision-check Ducky handles. Stable source namespace/category/identity belongs to a permanent correlation ledger in the transaction and backup. Repeat import recognizes existing identities and never overwrites subsequent Ducky edits/deliveries/cancellations. A later export with changed source content for a correlated identity is a counted conflict and fails semantic parity, not an ignored update. Compare via a private content fingerprint only while the record exists; tombstones retain identity alone. Rehearsal databases are disposable; the production target receives one import from the final stopped-source snapshot, never a stale rehearsal import. Forget/deletion leaves identity-only tombstones (no content/digest) so deleted records cannot resurrect. Retention must never remove the ledger or live series/checkpoints. Cross-record references resolve atomically; invalid references roll back everything.

Preferences live in non-authoritative owner-scoped persistence where needed. Frozen config always wins for owner, profile, timezone, destinations, channel roles, shared visibility, safety flags and authorization. Non-security presentation/scheduling preferences may override their documented native defaults only for the imported owner and only when explicitly selected by the active profile; incompatible explicit env settings are a parity conflict, never silently overwritten. Compare required config rather than write it. Optional unmapped active values fail closed. Verification exports only category counts and semantic pass/fail, never personal contents or exception details from input.

### 6. Explicit transition reconciliation

Source cursors are not interchangeable with Ducky snapshot hashes. Persist independently represented per-surface checkpoints and stable typed event identities with separate alert/digest settlement where audited behavior requires them. Preserve already-settled identities; first observation reconciles from the last known checkpoint through the stopped-notifier transition window before advancing.
